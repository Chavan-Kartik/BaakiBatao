## What is being measured

Each pack is a seeded, generated claim: a sampled policy, an admission of one of four
archetypes, an itemised bill composed to match it, and a deduction sheet settled **by the
engine's own arithmetic** so that the lawful baseline is exact. Zero to three fault
operators then inject unlawful rupees with a known clause and a known amount. A fault
counts as detected when the engine emits an `INCORRECTLY_APPLIED` finding on the same line,
citing the same clause, within ₹1 of the injected amount. A dispute no fault explains is a
false positive. Zero-fault packs are the control set; each is credited only with the lawful
deductions it actually contains.

Two profiles run over the same packs:

- **clean** — rows exactly as generated, categories by construction. This measures the
  waterfall alone: does it attribute known unlawful rupees to the right clause, and leave
  lawful ones alone.
- **degraded** — descriptions and digits perturbed the way OCR perturbs them, sheet rows
  occasionally missing, and categories assigned by the real tier-1 normaliser at its §14
  default threshold. This measures the system as far as it exists without AWS: the
  normalisation gate, the sheet matcher and the waterfall together.
- **degraded @ 0.52** — the same degraded packs with the normaliser at the threshold the
  calibration below recommends. Reported so the effect of adopting it is a number.

**Neither is a claim about real-world accuracy.** The corpus is generated, its phrasing is
ours, its noise model is a working assumption, and the lawful baseline is settled by the
same rules the engine enforces. See `fixtures/corpus/PROVENANCE.md`.

## Where the degraded profile loses faults

A miss is attributed to the first of three causes that applies: the line was **gated**
(the normaliser could not place it, so step 2 excluded it from adjudication), the line was
**unmatched** (its sheet row no longer paired with the bill row, so the engine had no
insurer cut to classify), or **engine** — the line reached the waterfall intact and the
engine still did not cite it. Only the last is an engine defect; the first two are the
extraction layer doing what it is supposed to do with input it cannot trust.

## What these numbers are not

- Not evidence about real Indian hospital billing. Phrasing, prevalences and amounts are
  sampled from distributions we chose.
- Not evidence that our encoding of the IRDAI circular matches how a practitioner reads it.
  The lawful baseline is settled by the same rules the engine enforces.
- Not a measurement of Textract. The degraded profile reproduces the *consequences* of OCR
  error at the row level; layout-dependent failures need the render path.
